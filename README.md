# Struct Layout Optimizer

从 C/C++ 头文件读取任意位宽字段定义，优化 struct/union 的字段排布，并输出优化后的 C++ 头文件及优化前后差异报告。

目标硬件按 8-bit BYTE 或 32-bit WORD 读取数据。工具不会创建 padding，也不会改变结构体总位宽。

## 优化规则

- 所有普通叶子字段计算跨 32-bit WORD 次数；
- 只有位宽严格小于 8 bit 的字段计算跨 BYTE 次数；
- 位宽大于或等于 8 bit 的字段不计算跨 BYTE；
- 普通字段可以重新排序，但不能拆分；
- 名称包含 `rsvd` 或 `reserved` 的保留域可以拆分；
- 同层 `rsvd` 总位宽保持不变，且不能跨嵌套层级移动；
- 不生成任何新 padding；
- 数组所有元素使用相同布局；
- 嵌套 struct/union 递归参与整体优化。

## 环境

- Windows、Linux 或 macOS；
- Python 3.10 或更高版本；
- 运行时无第三方 Python 依赖。

检查环境：

```powershell
python --version
```

## 快速开始

输入头文件：

```cpp
// types.hpp
struct Packet {
    uint17 a;
    uint8  b;
    uint15 c;
    uint3  packet_rsvd;
};
```

运行优化器：

```powershell
python optimize_header.py types.hpp --root Packet
```

默认在输入文件旁生成：

```text
types.optimized.hpp
```

指定输出路径：

```powershell
python optimize_header.py types.hpp --root Packet -o Packet.optimized.hpp
```

指定根结构体的绝对起始 bit 偏移：

```powershell
python optimize_header.py types.hpp --root Packet --start 24 -o Packet.optimized.hpp
```

如果省略 `--root`，工具使用头文件中最后一个 struct 或 union 定义。

## 命令行参数

```text
python optimize_header.py HEADER [--root TYPE] [--start BIT] [-o OUTPUT]
                          [--mode auto|exact|heuristic]
                          [--time-limit SEC]
                          [--beam-width N] [--branch-width N]
                          [--local-iterations N] [--random-seed N]
```

| 参数 | 含义 | 默认值 |
|---|---|---|
| `HEADER` | 输入 `.h/.hpp` 文件 | 必填 |
| `--root TYPE` | 要优化的顶层 struct/union | 最后一个定义 |
| `--start BIT` | 根类型绝对起始 bit 偏移 | `0` |
| `-o`, `--output` | 优化后头文件路径 | `<输入名>.optimized.hpp` |
| `--mode` | `auto`、`exact` 或 `heuristic` | `auto` |
| `--exact-threshold` | 自动模式使用精确搜索的最大直属字段数 | `10` |
| `--time-limit` | 启发式搜索时间预算（秒） | `10` |
| `--beam-width` | Beam Search 每层保留状态数 | `128` |
| `--branch-width` | 每个 Beam 状态扩展的字段数 | `12` |
| `--local-iterations` | swap/move 局部搜索次数 | `300` |
| `--random-seed` | 确定性随机种子 | `0` |

自动模式行为：

```text
直属普通字段 <= exact_threshold  → 精确穷举，保证全局最优
直属普通字段 >  exact_threshold  → 启发式搜索，在时间预算内返回最佳解
```

## 支持的头文件语法

### 任意位宽类型

```cpp
uint1  enabled;
uint7  channel;
uint12 sample;
uint17 counter;
```

### 标准 C/C++ 位域

位域宽度覆盖基础类型宽度：

```cpp
uint32_t mode  : 5;
uint32_t value : 17;
```

### 嵌套 struct、union 和数组

```cpp
struct Coordinate {
    uint17 x;
    uint15 y;
};

union SensorValue {
    uint31 raw;
    Coordinate coordinate;
};

struct Record {
    SensorValue sensor;
    uint12 samples[4];
    uint1 record_rsvd;
};

struct Packet {
    Record records[16];
    uint3 packet_rsvd;
};
```

### 可拆分 rsvd

以下名称会被识别为保留域：

```cpp
uint7 rsvd;
uint3 header_rsvd;
uint5 reserved_bits;
```

优化输出可能拆分为：

```cpp
uint2 rsvd_0;
uint5 rsvd_1;
```

所有片段位宽之和与原始保留域总位宽相同。

## 输出

命令行打印完整对比，包括：

- 优化前后总位宽；
- 跨 32-bit WORD 次数及减少量；
- 小于 8 bit 字段的跨 BYTE 次数及减少量；
- `rsvd` 片段数；
- 优化前后每个叶子字段的绝对 bit 范围。

生成的头文件示例：

```cpp
#pragma once

// Generated by struct-layout-optimizer.
// Size: 43 bit (unchanged)
// 32-bit crossings: 1 -> 0
// 8-bit crossings: 0 -> 0

struct Packet {
    uint17 a;
    uint15 c;
    uint8 b;
    uint3 rsvd_0;
};
```

嵌套类型以匿名内联 struct/union 输出，以准确保存该实例选中的内部布局。数组维度保持不变。

> 输出不会自动定义 `uint1`、`uint12`、`uint17` 等项目自定义类型。使用生成文件的工程必须已经提供这些类型或代码生成规则。

## Python API

正式输入推荐使用头文件解析 API：

```python
from cpp_header_parser import parse_header
from cpp_header_writer import render_optimized_header
from struct_layout_optimizer import (
    OptimizationConfig, comparison_from_outcome,
    format_comparison, solve_layout,
)

root = parse_header("types.hpp", root="Packet")
config = OptimizationConfig(mode="auto", time_limit=10)
outcome = solve_layout(root, start=0, config=config)
comparison = comparison_from_outcome(root, outcome, start=0)

print(format_comparison(comparison))
optimized_hpp = render_optimized_header(root, start=0, outcome=outcome)
```

主要接口：

- `parse_header(path, root=None)`：解析 C/C++ 头文件；
- `parse_header_text(source, root=None)`：解析头文件文本；
- `evaluate_original(type_, start=0)`：评估声明顺序；
- `optimize(type_, start=0)`：返回最优布局；
- `compare_layouts(type_, start=0)`：返回优化前后结果；
- `format_comparison(comparison)`：生成人类可读报告；
- `render_optimized_header(type_, start=0)`：生成优化后头文件文本。
- `solve_layout(type_, start=0, config=None)`：只运行一次搜索并返回可复用的模板、结果和搜索元数据。

报告中的搜索元数据包括：

```text
搜索模式       exact / heuristic
保证全局最优   是 / 否
搜索耗时       秒
```

## 当前限制

头文件解析器面向硬件描述用的 C/C++ 声明子集，目前不支持：

- 指针、引用、函数指针和动态数组；
- 模板、继承、虚函数和带方法的 class；
- 宏展开和条件编译语义；
- `alignas`、`#pragma pack` 和编译器 ABI padding；
- 一条语句声明多个字段，例如 `uint7 a, b;`；
- 匿名输入 struct/union 成员；
- 递归的按值类型。

解析器会移除注释和预处理行，但不会运行真正的 C++ 预处理器。

小结构体使用完整枚举并保证当前代价模型下的全局最优；大型结构体自动使用多起点布局、Beam Search、相位缓存、固定顺序 `rsvd` 动态规划和 swap/move 局部搜索。启发式模式不保证全局最优，但始终返回时间预算内找到的最佳布局，并在报告和生成头文件中明确标注。

仓库包含 120 个直属字段的真实头文件压力测试。默认建议大型输入使用 `--mode auto`，不要强制 `--mode exact`。

详细算法参见 [docs/algorithm.md](docs/algorithm.md)。
